# What's Different in This Fork

This is a customized fork of upstream [KMX415/meshpoint](https://github.com/KMX415/meshpoint), tuned for a SenseCap M1 "mega-sniffer" **and** a browser radio receiver. It tracks upstream (their v0.7.9 — backup/restore, RF Environment, Quick Deploy QR, Prometheus metrics — is merged in full), and on top of everything upstream provides, this version adds:

**RTL-SDR broadcast & utility radio listener** (entirely new)
- A cheap RTL-SDR dongle plugged into the Pi turns into a browser radio receiver and a family of decoders, all bundled plugins hosted on one shared **RTL-SDR** sidebar page (`plugins/apps/rtlsdr/`) — off by default, enable with `plugins.rtlsdr.enabled: true` plus whichever decoder(s) you want. Independent of the SX1302, so LoRa capture keeps running regardless of which of these is active; since the dongle can only be tuned to one frequency at a time, only one of them can run at once.
- **Radio** (`plugins/apps/radio/`) — FM broadcast, airband (AM), marine VHF/UHF, PMR446, 2 m / 70 cm ham, SSB (~24–1766 MHz). Modes **WFM / NFM / AM / USB / LSB**, with squelch, gain, and pre-encoder level controls. Two switchable radio faces — **Digital** (VFD readout + segmented VU) and **Analogue** (slide-rule dial + swinging-needle VU gauge under glass), persisted per browser — and a real-time **Web Audio VU meter** that follows the audio. **RDS** on FM (via `redsea`): station name, scrolling RadioText / now-playing, program type (PTY), and a block-error-rate signal-quality meter. A **preset stations picker** with category tabs, search, ★ favorites, and green "now playing" dots. The last RTL-SDR decoder to move onto this page — enable with `plugins.radio.enabled: true` after running `plugins/apps/radio/setup.sh` (builds `redsea` from source; `rtl_fm`/`ffmpeg` come from the shared `plugins/apps/rtlsdr/setup.sh` + base packages). `/api/listener/*` routes (kept unchanged from before this plugin existed) and its panel live in the plugin folder.
- **ACARS** (`plugins/apps/acars/`). Wraps [`acarsdec`](https://github.com/f00b4r0/acarsdec) + [`libacars`](https://github.com/szpajder/libacars) to decode aircraft VHF datalink messages on the European channels 131.525 / 131.725 / 131.800 / 131.825 MHz into a live log: flight/tail, message label, and text, with recognised standard types (CPDLC, ADS-C, media advisory, ARINC formats) expanded. Enable with `plugins.acars.enabled: true` after running `plugins/apps/acars/setup.sh` (builds the decoders from source). This is the reference for the [plugin architecture](#plugins) — its listener, `/api/acars/*` routes and dashboard tab all live in the plugin folder, wired through `register(reg)`, nothing in core.
- **RTL433** (`plugins/apps/rtl433/`); extracted out of core into a plugin as a second, simpler worked example. Runs [`rtl_433`](https://github.com/merbanan/rtl_433) directly — a single self-contained decoder covering weather stations, TPMS, remote sensors, and hundreds of other 433/315/868 MHz OOK/FSK devices, far broader than the paging-only P2000/Pagers/POCSAG protocols. Enable with `plugins.rtl433.enabled: true` after running `plugins/apps/rtl433/setup.sh` (a plain apt install, no build). Same Start/Stop and decoded-message log shape as ACARS; `/api/rtl433/*` routes and dashboard tab live in the plugin folder.
- **ADS-B** (`plugins/apps/adsb/`). Wraps [`dump1090`](https://github.com/MalcolmRobb/dump1090) for live air traffic tracking — a table (ICAO, flight, altitude, speed, track, position) from 1090 MHz transponder squitters, a "Metric units" toggle for meters/km-h instead of feet/knots, and a **Map** button (enabled once aircraft are tracked) opening a live OpenStreetMap (Leaflet) view with each aircraft plotted as a rotated plane icon colored by squawk, trailing its last couple of minutes of positions so you can see where it's been, and dropping off the map (though not the table) 60 seconds after its last update rather than lingering as a stale ghost for the full 5 minutes dump1090 itself keeps a contact around. Clicking any aircraft row, or a plane marker on the map, opens a **flight detail** modal — the tracked ADS-B fields plus, best-effort, registration/aircraft type/operator and route (origin–destination airport) from [hexdb.io](https://hexdb.io) and a real photo of the airframe from [planespotters.net](https://www.planespotters.net), both free public lookups queried straight from the browser. Enable with `plugins.adsb.enabled: true` after running `plugins/apps/adsb/setup.sh` (builds `dump1090` from source). `/api/adsb/*` routes and dashboard tab live in the plugin folder.
- **Pagers** (`plugins/apps/pagers/`). Decodes POCSAG512/1200/2400 pager traffic on 172.45 MHz via `rtl_fm | multimon-ng` into a live log. The original of the three pager kinds — P2000 and POCSAG (below) both split off from the code this used to share; this is the third and last, so nothing pager-related is built into core anymore. Enable with `plugins.pagers.enabled: true` after running `plugins/apps/pagers/setup.sh` (builds `multimon-ng` from source — `scripts/install.sh` no longer builds it at all). `/api/pagers/*` routes and dashboard tab live in the plugin folder.
- **POCSAG** (`plugins/apps/pocsag/`); the second of the three former pager kinds to split out (after P2000). Decodes POCSAG512/1200/2400 pager traffic on 439.9875 MHz via `rtl_fm | multimon-ng` into a live log — same Start/Stop and decoded-message log shape as Pagers (just a different band; both use the exact same decoders). Enable with `plugins.pocsag.enabled: true` after running `plugins/apps/pocsag/setup.sh` (builds `multimon-ng` from source). `/api/pocsag/*` routes and dashboard tab live in the plugin folder.
- **P2000** (`plugins/apps/p2000/`); split out of the Pagers/POCSAG code it used to share, since FLEX (P2000's protocol) is a different decoder entirely, not just a different frequency on the same POCSAG-family decoder Pagers/POCSAG use. Decodes Dutch emergency dispatch traffic on 169.65 MHz via `rtl_fm | multimon-ng` into a live log — same Start/Stop and decoded-message log shape as Pagers/POCSAG. Enable with `plugins.p2000.enabled: true` after running `plugins/apps/p2000/setup.sh` (builds `multimon-ng` from source). `/api/p2000/*` routes and dashboard tab live in the plugin folder.
- **DAB+** (`plugins/apps/dab/`); the first RTL-SDR decoder to move onto the shared RTL-SDR page, before every other one above (and Radio) followed. Wraps [`welle-cli`](https://github.com/AlbrechtL/welle.io) (welle.io's headless DAB/DAB+ decoder) for browser playback — pick a channel/ensemble (e.g. `12C` for the NPO nationals), then a station once it's decoded; ★ favorites jump straight to a channel + station in one click. A companion **Config** panel shows every channel `dab_channel_scan.py` found on your antenna (name, SNR, station list), with an editable display-name override per channel that the player's channel picker also uses, and can run the scan itself with live streamed output. Enable with `plugins.dab.enabled: true` after running `plugins/apps/dab/setup.sh` (a plain apt install, no build). `/api/dab/*` routes and both panels live in the plugin folder.

**Reticulum/LXMF messaging** (a plugin — `plugins/apps/reticulum/`, opt-in)
- Native LXMF messaging — a persisted Reticulum identity, an `LXMRouter`, announce-based peer discovery, and send/receive, on the **Reticulum** sidebar page (Peers roster with colored aspect pills, People/Infrastructure counts, a flat Messages summary, an admin-only Send tab, and a Settings tab) plus a topbar pill. The Send tab can optionally attach one image (≤5 MB) via LXMF's `FIELD_IMAGE`, shown as a thumbnail in the shared Messages chat view for both sides, or generate a **Paper message** instead of sending one — a real end-to-end-encrypted LXMF message (LXMF's `PAPER` delivery method) that's exported as a QR code rather than transmitted, for delivering a message with zero live network path at all; the recipient's own LXMF client scans it back in. Lives entirely in a plugin (`provides = ["service", "routes", "sidebar", "topbar"]`) — the first user of the `"service"` seam (a lifespan-managed background service). Enable with `plugins.reticulum.enabled: true`. Structured to never conflict with hardware you already run — meshpoint's client attaches to a locally-running [`rnsd`](https://reticulum.network) shared instance rather than opening a physical radio interface itself.
- **Set it up with `sudo meshpoint plugin setup reticulum`** — the plugin's `setup.sh` `pip install`s `lxmf` and installs + enables the `rnsd` systemd unit (`plugins/apps/reticulum/rnsd.service`). `rns` stays a core dependency (the `rnsd` binary + `rnodeconf` for the RNode flasher); `lxmf` is Reticulum-messaging-only. `rnsd` runs as its own service, sharing meshpoint's config directory so the shared-instance RPC channel works, deliberately **not** a dependency of meshpoint's own service. Its interfaces config is generated from `plugins.reticulum.*` on every start — nothing to hand-edit.
- **Browse tab — a minimal [NomadNet](https://github.com/markqvist/NomadNet) browser.** Pick a `nomadnetwork.node` peer (or type a `<hash>:/page/index.mu` address) and it fetches the node's Micron pages over RNS Links and renders them — links, page forms, back/forward history, `/file/...` downloads. `nomadnetwork.node` rows on the Peers tab get a "Browse" button. The Micron renderer is ported from reticulum-meshchat's `MicronParser.js` (MIT).
- **Host your own NomadNet node** (opt-in, `plugins.reticulum.node_enabled`, toggle on the Settings tab). Meshpoint registers a `nomadnetwork.node` destination on the same identity as its LXMF address — so it's both "message me" and "browse me" on one hash — and serves a built-in index page with live stats plus any `.mu` files you drop in `node_pages_dir`.
- **Telemetry, both directions.** *Publish* (opt-in, `plugins.reticulum.telemetry_enabled`): periodically send this box's host stats — CPU/SoC temperature, load, RAM/disk, a status line, and opt-in location from the Configuration → GPS pin — to a collector LXMF address as a Sideband-compatible `FIELD_TELEMETRY` frame. *Collect*: a **Telemetry** tab on the Reticulum page shows the latest reading from every node that publishes one, and plots the ones with a location on a small map. `GET /api/reticulum/telemetry` / `.../telemetry/peers`, live over a `reticulum_telemetry` WebSocket event.
- **LXMF propagation, both directions.** Run a store-and-forward relay for others (`propagation_enabled` — messages for offline peers held on this box until they sync), *and/or* use someone else's relay as your own propagation node (`propagation_outbound_node` — a dropdown of heard `lxmf.propagation` peers on the Settings tab): your messages to offline peers route through it, and a "Sync inbox" button on the Reticulum page pulls anything parked there for you, with live transfer state. Optional timed auto-sync. `GET /api/reticulum/propagation` + admin `POST .../propagation/sync`.
- **Contacts — your own names for peers.** The Peers drawer has a **Contact** section (admin only): give a destination hash your own name (plus an optional note and a "mark as known" flag), stored locally in `data/reticulum/contacts.json` and never announced. That name then wins across the Peers/Activity tables, the Messages list and the Send picker; the announced name moves to an "announced as …" sub-line and flags if it later changes. `GET /api/reticulum/contacts` + admin `PUT`/`DELETE`.
- **The Reticulum page's Settings tab** edits display name, the NomadNet timeout, RNode radio (serial port dropdown from the shared USB-device picker, frequency/bandwidth/TX power/SF/CR), the TCP backbone host/port, and an **Extra interfaces** list — add any number of `TCPClientInterface` / `TCPServerInterface` / `UDPInterface` entries beyond the two built-ins, validated on save and written into `rnsd`'s config; a "Restart rnsd" button applies interface changes without a full meshpoint restart.
- **Configuration → Firmware — flash real RNode firmware onto a "dumb modem" board** (stays in core — it's hardware provisioning), 13 supported boards, flash + EEPROM provisioning + firmware-hash in one step via `rnodeconf`. The standalone Heltec-V4 Reticulum-node firmware card is there too.

**Expanded multi-protocol capture**
- **LoRaWAN passive sniffing** — full MAC decoder (Join / Data / Rejoin), a dedicated LoRaWAN dashboard panel, and `/api/lorawan/*` endpoints, using the SX1302 "dual sync-word" trick (ch0–ch7 on LoRaWAN 0x34, ch8 on Meshtastic 0x2B).
- **EU868 5-channel LoRaWAN plan** (867.9 / 868.1 / 868.3 / 868.5 / 868.7 MHz) across RF0's full IF window — the 3 mandatory uplinks plus 2 extra TTN channels.
- **Up to 4 MeshCore USB companions** plus a Meshtastic-433 serial source → 5 networks captured at once.
- **MeshCore per-packet metadata** — frequency/SF read from the companion's radio config, hop count decoded from the MeshCore `path_len`, and each companion's packets labeled by source.
- **Up to 40 MeshCore user channels** (slots 1–40, slot 0 stays Public) — raised from 7.
- **Replies route back through the radio that can actually hear the contact** — on a multi-radio box, a DM reply to a contact heard only on a 433 MHz companion/stick now goes back out on 433, not always the one "primary" companion/concentrator; MeshCore channel broadcasts fan out to every connected companion. The chat header shows a small pill naming which specific companion/stick a conversation is on.

**Hardware page & spectrum**
- **Band spectrum card** — the concentrator module's onboard SX1261 companion chip (not a USB radio) sweeps the whole region band (100 kHz steps, EU868: 863–870 MHz) and draws a live spectrum chart with median + peak level and the LoRaWAN / Meshtastic / MeshCore channel positions overlaid; "Sweep now" button, hover readout, `GET /api/device/spectrum`. Requires `radio.sx1261_spi_path` (e.g. `/dev/spidev0.1`) in `local.yaml`; cadence via `radio.spectrum_sweep_interval_seconds`.
- **RF Environment works on the SenseCap M1** — upstream marks spectral scan unavailable on the M1; this fork's `sx1261_spi_path` support powers upstream's RF Environment tab with live hardware scans here (and its histogram's endless-page-growth bug is fixed).
- **RF Environment companion for boards with no SX1261 at all** — RAK2287 is datasheet-confirmed to have no SX1261, so no config change can ever enable a real hardware spectral scan there. `extra/rfenv_companion` (Heltec V3, own SX1262 + antenna) samples real ambient RSSI over USB serial and feeds the same histogram/noise-floor card *and* the Band Spectrum sweep card instead of the packet-derived fallback; the board's OLED also works standalone, independent of any Pi connection — a live band-scan view plus a button-triggered local histogram scan.
- **Concentrator channels card** — read-only table of all 9 SX1302 slots (frequency, BW, SF, sync word, protocol, RF chain, state), derived from the same channel-plan code the radio runs.
- **Unified protocol cards** — "Meshtastic Configuration" (radio settings + channel list in one card) and a matching MeshCore layout.
- **Configuration → Serial and → MeshCore show live readouts per USB device** — Node ID, frequency, bandwidth, SF, TX power, firmware version, and hardware model for each connected stick or companion, read straight from the device itself, with a "Check for updates" button per device comparing against the latest upstream firmware release on GitHub.
- **Configuration → Firmware — flash any connected USB-serial board straight from the dashboard, no separate machine needed.** Four cards, one per protocol: **MeshCore** and **Meshtastic** each download an official prebuilt release (`esptool`, no compiling) with a Version picker (latest, or pin a specific release) and a searchable Board field pulled live from that release's own manifest — MeshCore also has a Flavor picker (USB, for a board that connects to this dashboard; BLE, for a spare board headed to someone using the official phone app instead). **POCSAG** (the **DAPNET** plugin's own card) compiles `plugins/apps/dapnet/pocsag_companion` from source instead, via a self-contained `arduino-cli`/ESP32 toolchain `scripts/install.sh` sets up automatically — no GitHub release to pick, so Compile and Flash are separate steps. **Pager** compiles `extra/pager_client` the same way, simplified to a single board (Heltec V3 only, no board picker) with no USB companion to pause/resume around a flash — its own "Capcodes to program" field (comma-separated) lets this specific physical unit be programmed with its personal capcode plus any group/team addresses, injected into the sketch right before each compile. All four "Device to flash" pickers list *every* currently-connected USB-serial device (with a "↻ Rescan USB" button), not just an already-configured one, so a spare or borrowed board can be flashed without adding-then-removing a permanent entry first — and always require picking the target explicitly, never defaulting to whichever board happens to already be configured. Meshtastic and MeshCore each have an **"Erase everything" checkbox**, on by default (full-chip erase, needed for a board currently running something else entirely, e.g. the DAPNET companion below); turning it off upgrades a board already running that protocol's firmware in place, without wiping its channels/node database (Meshtastic) or identity/contacts/channels (MeshCore).
- **Rename any USB stick or companion straight from the dashboard, per device** — no Bluetooth needed. Each Serial/MeshCore device row has its own name field(s), a "Send advert after save" checkbox, and a Save button, so multiple sticks/companions don't have to share one identity or need a laptop running the official Meshtastic app.
- **Node drawer recent packets** — every node shows its last 15 packets (time, type, RSSI/SNR).
- **SNR distribution chart** on Stats next to the RSSI histogram; signal stats ignore implausible near-field readings (> −20 dBm).
- **Relay tuning from the dashboard** — burst size and the min/max RSSI relay window are editable on Configuration → Transmit.
- **Temperature-driven PWM fan control** (opt-in, SenseCap M1 only) — the onboard fan ramps speed with CPU temperature instead of running flat-out or not at all; `fan:` in `local.yaml`.
- **Thermals card** — 6 h of CPU temperature + fan duty history as two stacked charts on the Hardware page (`GET /api/device/thermals`); shown only when fan control is enabled.
- **Status LED** (opt-in, SenseCap M1 only) — the case LED becomes a glanceable health light: steady on = all capture sources healthy, brief flicker = packet captured, 1 Hz blink = a source is down, dark = service not running; `led:` in `local.yaml`.
- **User button** (opt-in, SenseCap M1 only) — short press adverts on every TX-capable radio (Meshtastic 868 + 433, MeshCore), long press (3 s) restarts the service; LED feedback for every gesture; `button:` in `local.yaml`.
- **Configuration → Peripherals page** — edit the fan, status LED, and user button settings above from the dashboard instead of hand-editing `local.yaml`.
- **CSV export** — an Export button on each protocol page (LoRaWAN / Meshtastic / MeshCore) downloads the active tab's dataset: all captured packets, or the full device/node/contact census. Streamed straight from the database (so "all packets" really is all), UTF-8 with a BOM so Excel handles the emoji, and LoRaWAN packet exports flatten DevEUI/FCnt/FPort/MIC into their own columns for coverage analysis.
- **MeshCore repeater monitoring** (opt-in) — MeshCore nodes advertise identity only, so Meshpoint can actively poll repeaters you operate (`req_status`/`req_telemetry`, like the phone app) for battery, uptime, airtime, packet counters, noise floor and LPP sensors. A dedicated **Repeaters** page shows a Health / Sensors / History card row plus a Trends chart of the voltage/temperature/humidity/pressure history, and its neighbour count opens a modal listing each one (freshest-first, names resolved against the known roster). Each poll also feeds the reported neighbours into the roster (placeholder nodes, `nb:`-tagged packets — same convention `scripts/import_contacts.py`'s manual import uses, just live), so the Health card can show a **Farthest neighbour** distance/SNR/name per repeater, measured from that repeater's own position rather than Meshpoint's (a repeater can be a remote site). Configured from the dashboard at **Configuration → Repeater Poll** (enable/interval, add/rename/remove repeaters) — no more hand-editing `repeater_poll:` in `local.yaml`.

**Roles, config & self-update**
- **Viewer role locked down server-side** — all write endpoints require admin; channel PSKs/keys are redacted for viewers; admin-only links show a toast instead of navigating away.
- **Web server port from config** — `dashboard.host`/`dashboard.port` in `local.yaml` via a launcher that falls back to `0.0.0.0:8080` if the config is broken or the port unbindable.
- **Telemetry history is now auto-pruned too** — packets already had an automatic row cap; telemetry (battery/voltage/temperature history) could grow unbounded until this fork added a matching `max_telemetry_retained` setting, editable from Configuration → Advanced alongside the existing packet cap.
- **Self-update follows whichever fork you actually cloned** — version checks and the apply chain derive the GitHub repo from your own `origin` remote (falling back to the upstream project if it can't be determined), so a fork just works with zero config; sudoers/safe.directory repairs are self-installing, update checks work on dev checkouts (sudo only when the repo is root-owned), "Check for updates" lists the incoming commit messages so you can see what an Apply brings, a **Latest commits** list shows the last five commits on the channel's GitHub branch (date, SHA, message), a **Custom branch** field offers the resolved repo's real branches as autocomplete suggestions, and the release-notes preview groups its bullets under the changelog's category headings.
- **Automatic update checks** (on by default) — a background task periodically re-checks for updates using the same git-fetch logic as the manual button, and an "Update available" pill appears under the device status at the top of the sidebar the moment one's found; click it to jump straight to Settings → Updates. Interval and on/off are editable from that same page; `update_check:` in `local.yaml`.

**Contacts / neighbours tooling**
- `import_contacts.py` imports a MeshCore contacts/neighbours list into the node DB, with clock-skew-immune timestamps (`now − secs_ago`) and freq/SF stamping.
- `scripts/repair_neighbour_timestamps.py` + `scripts/backfill_meshcore_signal.py` fix bad past/future timestamps and backfill freq/SF on old rows.
- `scripts/edit_contact.py` interactively looks up and corrects a node's stored name/GPS in the database (e.g. a stale fix on a node whose real location you know) — shows the current values, confirms before editing, and confirms again before writing.

**UI / UX**
- **Mesh topology graph + map** — a Topology page draws the mesh as a force-directed graph: Meshtastic traceroute chains, direct receptions by this box, and MeshCore neighbour SNR become nodes and edges you can drag, zoom, and filter. A Graph|Map switch projects the same network onto real map tiles, an "all positions" layer shows every positioned-but-unlinked node as a faint scouting dot, and with repeater polling enabled the graph refreshes itself — each poll fetches the repeater's own neighbour list (`fetch_all_neighbours`), so every polled repeater becomes a live star. `GET /api/topology/graph`.
- **Configurable map tile source, for offline/emergency use.** `dashboard.map_tile_url` (default: the public OSM server, today's unchanged behavior) feeds both the Dashboard and Topology maps through one shared helper (`frontend/js/map_tile_source.js`) instead of each hardcoding the URL, and applies immediately — no restart. Pair it with the community **offline-map** plugin (`meshpoint-plugins/apps/offline-map`), which downloads OSM tiles for an area via a managed [Cyclenerd/offline-map-tile-downloader](https://github.com/Cyclenerd/offline-map-tile-downloader) subprocess and serves already-downloaded ones straight off disk (no downloader process needing to stay running) — its own Settings page has a "Dashboard map source" picker that points this at whatever's been downloaded, so both maps keep working with zero internet reachable at all.
- **Incoming-message notifications** — corner toast with sender + snippet (click jumps to the conversation) and an optional soft notification sound; independent per-browser toggles in Settings → System.
- **Topbar theme toggle** — 18 themes, each with a per-theme icon. Built-ins (`dark`, `light`, `high-contrast`, `sunlight`) live in `frontend/themes/<id>/`; extra / community themes drop into `plugins/themes/<id>/` (Solarized Dark, Nord, Gruvbox Dark, Amber Mono, Green CRT, Dracula, Catppuccin Mocha, Rosé Pine, Everforest Dark, One Dark, Kanagawa, GitHub Dark, Ayu Mirage, plus a **Colour-blind safe** theme using the Okabe-Ito palette). Each is a `theme.json` + `theme.css`; the picker builds its list from `GET /api/themes`, so a new theme is "add a folder and restart", no code change. **Settings → Themes** sets the server-wide default and has a live theme builder — preview palette edits on the whole dashboard, then **Save to device** (writes it into `plugins/themes/`, no restart) or download a `theme.css` + `theme.json` to share. An **Installed themes** list on the same page lets you delete themes you saved yourself; the shipped/community set is locked and can't be removed or overwritten from there.
- **24-hour time** across the whole dashboard.
- **Metric defaults** (Celsius + kilometers) for a fresh browser.

**Plugins**
- **App plugins** — optional features (an RTL-SDR listener + its API routes + a dashboard tab, a whole top-level sidebar page, content injected into another plugin's page, or a capture source + protocol identity joining the core packet pipeline directly) that live in `plugins/apps/<id>/` instead of core, wired through a `register(reg)` entry point against a small facade over Meshpoint's route/listener/capture-source/protocol registries. They load from `src/plugins/apps/` (bundled) or `plugins/apps/` (drop-in); a `plugin.toml` manifest declares the API version, capabilities (`listener`/`routes`/`panel`/`sidebar`/`hook`/`capture`/`protocol`/`topbar`/`service`), apt/`setup.sh` dependencies, and frontend files. Loading is opt-in per plugin (`plugins.<id>.enabled` in `local.yaml`) because an in-process plugin runs with the service's privileges. The **ACARS** decoder is the reference plugin (`plugins/apps/acars/`) for `listener`/`routes`/`panel`; **RTL433** (`plugins/apps/rtl433/`), **ADS-B** (`plugins/apps/adsb/`), **P2000** (`plugins/apps/p2000/`), **POCSAG** (`plugins/apps/pocsag/`), **Pagers** (`plugins/apps/pagers/`), **DAB+** (`plugins/apps/dab/`) and **Radio** (`plugins/apps/radio/`) are further examples, all extracted out of core the same way — P2000, POCSAG and Pagers were originally one shared file (`src/audio/pager_listener.py`) covering all three kinds, split out one at a time until nothing pager-related was left in core; Radio was the last RTL-SDR tab extracted, so nothing RTL-SDR-related is built into core anymore — all of it, including the shared **RTL-SDR** host page itself (`plugins/apps/rtlsdr/`), is opt-in plugins now. **Hello World** (`plugins/apps/hello-world/`) is the reference for `sidebar` — a whole new top-level nav page, not just a tab hooked into another plugin's page; **Hello World Hook** (`plugins/apps/hello-world-hook/`) is the reference for `hook` — content injected into *another* plugin's already-rendered page (Hello World's own) instead of owning a page of its own, which a host page opts into via `window.mountPageHooks(...)`. **DAPNET** (`plugins/apps/dapnet/`, see below) is the reference for `capture`/`protocol` — unlike every plugin above, it isn't RTL-SDR-shaped at all: a real `CaptureSource` joins the pipeline unconditionally at boot instead of an on-demand `/start`-triggered listener, and it owns decode + classification for a protocol identity (`OpenProtocol("dapnet")`) that isn't one of the core `Protocol` enum's members. It's also the reference for `topbar` — a plugin's own persistent topbar status chip (`window.registerTopbarChip`), the same visual language as the built-in Meshtastic/MeshCore/Serial/Pager chips. **Reticulum** (`plugins/apps/reticulum/`, extracted from core) is the reference for `service` — a lifespan-managed async background service (an object with `start()`/`stop()`, the same shape as a companion service), for a plugin that isn't a subprocess listener or a packet-pipeline source; **Hello Service** (`plugins/apps/hello-service/`) is the minimal example. See [Configuration → Plugins](CONFIGURATION.md#plugins) for using one, or [PLUGINS.md](PLUGINS.md) for writing one.
- **Settings → Plugins** — every discovered plugin (built-in or community) in one page, with a toggle for its `enabled` flag (admin-only, saved to `local.yaml`). Since plugins load once at startup, each card also shows whether it's currently loaded and flags when a restart is needed to apply a change. A plugin that ships a `[deps] check` probe (Reticulum is the first) also shows a live **"⚠ Setup needed"** / **"✓ Dependencies installed"** verdict — the loader runs the probe at boot, and a **Re-check** button re-runs it so running the setup step on the device clears the warning without a restart. When setup is needed, a **Run setup** button streams the plugin's `setup.sh` output into a modal (same thing `sudo meshpoint plugin setup <id>` does, no SSH needed) and offers Enable + Restart once it succeeds.
- **Plugin sources** — the same page lets you add a **GitHub repo of plugins/themes** as a source (paste the URL, confirm an explicit trust prompt — a source can install code that runs with the service's privileges and a `setup.sh` that runs as root). Meshpoint reads a `repo.json` catalog at the repo root, shows each entry's version and install/update state (with a per-source count up front), and **Install** pulls just that entry's subtree from GitHub (`…/tarball/<ref>`, no `git` on the box), rejects unsafe archive members, re-validates the real `plugin.toml` with its own parser, and drops it in `plugins/apps/<id>/` — disabled, so enabling and setup stay deliberate steps. Sources and each install's provenance are saved to `local.yaml`, surviving restarts and self-updates. The whole subsystem is off by default and stays that way until `plugin_sources_enabled: true` is hand-set in `local.yaml` and the service restarted — deliberately no API route or dashboard toggle can flip it, so a compromised admin session can't re-enable it on its own; the confirm prompt only proves the *current* session consents. Publish your own: [PLUGINS.md → Publishing a plugin repository](PLUGINS.md).

> Because this is a fork, a dashboard **Update** (which runs `git reset --hard origin/main`) will overwrite these changes unless your `origin` remote points at this fork rather than upstream.
