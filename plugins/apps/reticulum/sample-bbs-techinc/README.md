# TechInc Mesh BBS — a ready-made NomadNet page set

A small **read-only BBS** for a Meshpoint node that hosts a
`nomadnetwork.node` (`plugins.reticulum.node_enabled: true`). Splash
screen + a menu of cross-linked Micron pages, in the spirit of a dial-up
board. It's browse-only — nothing here is an executable NomadNet page, so
there's no guestbook or door games; "leave a message" means *reply over
LXMF to the node's address*.

## Pages

| File | `/page/…` | What |
|---|---|---|
| `index.mu` | `/page/index.mu` | Splash + main menu (replaces the generated landing page) |
| `techinc.mu` | `/page/techinc.mu` | About the hackerspace — address, open evening, membership |
| `meshpoint.mu` | `/page/meshpoint.mu` | About Meshpoint — what it is, the protocols, the dashboard (generic, reusable as-is) |
| `mesh.mu` | `/page/mesh.mu` | What the node relays, frequencies, how to reach it, how to get your own node |
| `links.mu` | `/page/links.mu` | Other NomadNet nodes + Reticulum resources |

`/page/info.mu`, `/page/nodes.mu`, and — when the matching URL is set on the
Settings tab — `/page/spacestate.mu` (`node_spaceapi_url`) and
`/page/events.mu` (`node_events_ical_url`) are generated by Meshpoint. The
menu just links to them; there's no file to deploy.

## Live bits — set two URLs on the Settings tab

Menu items **4** (`events.mu`) and **6** (`spacestate.mu`), and the "The
space is right now: {spacestate}" line on the splash, are all driven by
Meshpoint-generated pages that only exist when you point them at a feed —
Reticulum → **Settings** tab → *node hosting*:

- **SpaceAPI URL** (`node_spaceapi_url`) → `/page/spacestate.mu` + the
  `{spacestate}` token (a live OPEN/CLOSED word usable in any of your `.mu`
  pages). Find yours at `directory.spaceapi.io`.
- **Events iCal URL** (`node_events_ical_url`) → `/page/events.mu`, the next
  dozen upcoming events. Any `.ics` feed works — for TechInc it's
  `https://wiki.techinc.nl/TechInc.ical`.

Leave one blank and its menu item 404s (and `{spacestate}` stays literal) —
trim the dead line/menu entry from `index.mu` if your node doesn't need it.
Both feeds are fetched once at boot, then only when someone actually opens
the page — an idle node never polls them.

## Deploy

**Via the dashboard (easiest):** Reticulum page → **Pages** tab → for each
file, **New**, name it (`techinc.mu` etc.), paste, **Save**. It's served
immediately. Start with `index.mu`.

**By hand:**

```sh
sudo cp plugins/apps/reticulum/sample-bbs-techinc/*.mu \
        /opt/meshpoint/data/reticulum/pages/
sudo systemctl restart meshpoint     # a restart registers the new files
```

## Before you ship it

The address and contact details are the real TechInc ones. If you're
adapting this for another space, or before the first announce, still check:

- `index.mu` / `techinc.mu` — space name, address, contact block
- `mesh.mu` — the frequencies + preset must match this node's real config
- the SysOp callsign in `index.mu`
- `node_spaceapi_url` + `node_events_ical_url` (Settings tab) so menu items
  4 and 6 and the `{spacestate}` line resolve

To turn a node name in `links.mu` into a real link you need that node's
32-hex destination hash: `` `[Name`<hash>:/page/index.mu] ``.

## Micron gotchas (learned the hard way)

- `` `c `` centres **each line on its own** → multi-line ASCII art must be
  left-aligned or it fragments. The MESHPOINT banner here is left-aligned.
- Backtick `` ` `` is Micron's only escape char — keep it out of ASCII art.
- Keep lines under ~130 chars for phone / MeshChat clients.
- A `` `Fxyz `` colour code needs **exactly 3 hex digits** right after the
  `F` (`` `F38f ``), or it eats your text.
